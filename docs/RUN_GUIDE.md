# Run the application and models

[Main README](../README.md) · [Project walkthrough](README.md)

This guide uses Windows PowerShell first because the project is intended to run locally on your computer. Commands assume the terminal is inside `Enterprise_HR_RAG_Full_Project`, the folder containing `start.py`.

## Before the first run

You need Python 3.11 or 3.12, the extracted project folder and internet access to install packages. Do not run Python files directly from inside the ZIP. Keep the included `data/source/`, `config/` and `ui/` folders beside the code.

The default mode does not need a GPU, Docker, Redis, a downloaded embedding model or an API key. Groq mode needs a valid key and a network connection. Dense retrieval needs the extra setup shown later.

## A. First local run

Create one virtual environment:

```powershell
py -3.12 -m venv .venv
```

Use `py -3.11` instead if that is your installed version. Install the required packages into this environment:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Start both services:

```powershell
.\.venv\Scripts\python.exe start.py
```

Wait for startup to finish, then open [http://localhost:8501](http://localhost:8501). Leave the terminal open.

The launcher performs these steps for you:

1. Creates `.env` from `.env.example` if needed and prepares a private demo session token.
2. Starts the API on `127.0.0.1:8000` using the same Python environment.
3. Checks process liveness and prepares the approved documents for the local demo.
4. Starts Streamlit on `127.0.0.1:8501` and connects it to the API.

In **People & policies**, ask “How many sick leave days are permanent employees entitled to?” Expect the policy evidence for 10 working days and relevant qualifications. In **IT & operations**, ask “What is the Payments database RPO in the backup SOP?” Expect its 15-minute PDF table entry.

Open **View evidence** under the answer to confirm the source name and location. Local output is labelled **SOURCE EXCERPTS**.

## B. Enable the Groq generation model

Press Ctrl+C to stop the launcher. Open the generated configuration file:

```powershell
notepad .env
```

Set these entries, replacing the key placeholder with your own key:

```dotenv
AUTH_MODE=demo
RETRIEVAL_MODE=lexical
GENERATION_MODE=auto
ENABLE_EXTERNAL_LLM=true
GROQ_API_KEY=YOUR_ACTUAL_GROQ_API_KEY
GROQ_MODEL=llama-3.3-70b-versatile
ALLOW_EXTERNAL_CONFIDENTIAL=false
```

Leave the `DEMO_API_TOKEN` generated by the launcher in place. Save `.env`; do not save it as `.env.txt`. Restart:

```powershell
.\.venv\Scripts\python.exe start.py
```

Ask an in-scope policy question. **DOCUMENT ANSWER · Generated with Groq** indicates a successful generated result. A warning plus **SOURCE EXCERPTS** indicates fallback; read the warning to distinguish missing credentials, model access, rate limits, timeouts or citation problems.

The model runs on Groq's service. No Llama weights are downloaded by this mode. Do not put the provider key in Python code or the UI's Session token box. Settings are loaded from the project-root `.env`; an explicitly set operating-system environment variable takes precedence over the file.

If the configured model is unavailable to your account, set `GROQ_MODEL` to a model that your account supports with the request's JSON-object output mode, then restart. The supplied code does not create an account or validate a key until a question triggers a provider request.

## C. Return to local excerpts

Stop the application, edit `.env`, and set:

```dotenv
RETRIEVAL_MODE=lexical
GENERATION_MODE=extractive
ENABLE_EXTERNAL_LLM=false
REDIS_URL=
```

Restart with the same `start.py` command. With base dependencies installed and the bundled files available, this path needs no cloud model call or external retrieval service.

## Optional dense retrieval with Qdrant

This changes how evidence is found. It does not by itself enable generated answers. You can combine it with either Groq or local excerpts.

### 1. Install extra dependencies

Stop the launcher. Install Docker with Compose support and start Docker, then run:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dense.txt
docker compose up -d qdrant
```

`requirements-dense.txt` includes the base dependencies. The bundled Compose file exposes Qdrant on local port 6333 and stores its data in a named volume.

### 2. Configure retrieval

Edit `.env`:

```dotenv
RETRIEVAL_MODE=dense
EMBED_MODEL=BAAI/bge-small-en-v1.5
EMBED_REVISION=main
QDRANT_URL=http://localhost:6333
QDRANT_COLLECTION=enterprise_bge_small_v1
CHUNK_TOKENS=180
CHUNK_OVERLAP=30
```

Keep your chosen generation settings from section B or C. The chunk-size settings count words in this implementation; the embedder separately validates its token limit.

### 3. Start and check

```powershell
.\.venv\Scripts\python.exe start.py
```

The first dense initialization downloads the configured embedding model and can take longer. Ensure the model host and Qdrant are reachable. If the interface reports a startup timeout while preparation continues, check the terminal and use **Connection settings → Check connection** after the model is ready.

The embedding model runs locally through Sentence Transformers. Qdrant holds its passage vectors. A model with a different embedding dimension needs a compatible new `QDRANT_COLLECTION`; do not reuse an incompatible collection. The application separates runtime state by retrieval settings to avoid reusing stale index metadata.

### Optional Redis caching

Caching is not needed for a first run. To enable it with the dense dependency set already installed:

```powershell
docker compose up -d redis
```

Set `REDIS_URL=redis://localhost:6379/0` in `.env` and restart. Both services can also be started together with `docker compose up -d`. To stop the Compose services later, run `docker compose stop`.

## Restart after changing configuration or sources

Use Ctrl+C in the launcher terminal, save the changes, then run:

```powershell
.\.venv\Scripts\python.exe start.py
```

Restarting imports changed bytes for approved bundled originals when `AUTO_IMPORT_DATASET=true`. A new filename needs an approved dataset policy first. The application preserves explicit document deletions across restarts.

Do not delete the data folder to solve an ordinary provider-key problem. A Groq key change needs a restart, not document reparsing or a new virtual environment.

## Regenerate parser exports

```powershell
.\.venv\Scripts\python.exe scripts/parse_dataset.py
```

This writes the local JSONL exports and their parsing report. It does not start the application or update the active index on its own. The current six originals produce 442 blocks, including 187 table rows, as recorded in the supplied parsing report.

## Use different ports

If default ports are already occupied:

```powershell
.\.venv\Scripts\python.exe start.py --api-port 8001 --ui-port 8502
```

Open [http://localhost:8502](http://localhost:8502). The launcher points the UI at the matching API port automatically.

## Troubleshooting in order

1. **Check the folder.** Confirm `start.py`, `requirements.txt`, `data/source/` and `.env.example` exist in the extracted root. Run commands there.
2. **Check the interpreter.** Use `.\.venv\Scripts\python.exe` for both installation and startup. A globally installed package may not be available in `.venv`.
3. **Read the launcher error.** An occupied port, missing package or invalid configuration should be addressed before retrying the browser.
4. **Check connection and document readiness.** Use **Connection settings → Check connection**. The endpoint `/health` only confirms a running process; it does not test the corpus or Groq account.
5. **Check the selected area.** Research is empty. Demo permissions expose four source documents across HR and operations, not the restricted report and training workbook.
6. **Check the generation settings.** Ensure `ENABLE_EXTERNAL_LLM=true`, `GENERATION_MODE=auto` or `groq`, a real key and an accessible model. Restart after editing `.env`.
7. **Read the provider warning.** Authentication, rate-limit, model and timeout failures have different causes. If an external request fails, the cited local fallback can still work.
8. **Check whether the question is supported.** Geography and live employee balances are outside this corpus. A clear “not found” answer is expected for those questions.

If PowerShell cannot find `py` but `python --version` reports Python 3.11 or 3.12, use `python -m venv .venv` for the creation step. Environment activation is unnecessary, so PowerShell activation-policy errors can be avoided by using the explicit executable paths shown throughout this guide.

## Verify your installation

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q app.py start.py hr_rag scripts tests
```

Base requirements include pytest. The optional Qdrant test is skipped if its package is absent. Tests simulate Groq responses; they do not prove that your actual key works. For that, run section B and confirm that a real in-scope question returns **DOCUMENT ANSWER · Generated with Groq** without a fallback warning.

For exact historical validation scope, read [reports/VALIDATION_SUMMARY.md](../reports/VALIDATION_SUMMARY.md).

## macOS/Linux command equivalents

Use Python 3.11 or 3.12 from the project folder:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python start.py
```

For optional dependencies use `.venv/bin/python -m pip install -r requirements-dense.txt`. For parsing and tests, substitute `.venv/bin/python` for `.\.venv\Scripts\python.exe`. Docker commands and `.env` entries are the same.
